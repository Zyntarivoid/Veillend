The application is a NestJS monolith organized around feature modules (`admin`, `assets`, `auth`, `indexer`, `portfolios`, `protocol`, `stellar`, `transactions`, `wallet`) wired together in `src/app.module.ts`. Cross-cutting concerns are centralized under `src/common` (logging, DTOs, interceptors) and `src/config` (typed config classes validated with class-validator). Persistence uses Prisma with a PostgreSQL datasource defined in `prisma/schema.prisma`, which models Users, Sessions, Assets, Positions, TransactionHistory, SyncCheckpoint, Admin, and IndexerCheckpoint; migrations live under `prisma/migrations`. The `IndexerModule` consumes `StellarModule` (Horizon + Soroban RPC clients) to stream on-chain events and persist them, while read paths go through per-feature services that query Prisma. Authentication is JWT-based via `@nestjs/jwt` and `passport-jwt`, with an `AdminGuard` and `JwtAuthGuard` protecting routes. Global pipes, guards, interceptors, and filters are registered at the root module level (throttling, correlation-id CLS context, exception filtering, response transformation).
